# MATLAB OOP 分阶段学习计划

本文配合仓库根目录 README 使用。建议每个阶段按“理解概念 → 阅读现有示例 → 独立编码 → 编写测试 → 总结设计决策”的顺序完成。

## 学习闭环

```mermaid
flowchart LR
    A[阅读概念] --> B[运行示例]
    B --> C[修改实验]
    C --> D[独立实现]
    D --> E[编写测试]
    E --> F[复盘与记录]
    F --> A
```

## 阶段一：读懂最小类

**目标：** 能读懂 `classdef`、属性、方法和构造函数。

任务：
- 阅读 [CH00201](../CH002/CH00201/README.md) 与 [CH00202](../CH002/CH00202/README.md) 中的 `Point2D`。
- 创建对象，读取和修改属性，调用实例方法。
- 为二维点添加平移、距离和显示功能。

验收：独立写出可运行的 `Point2D` 类，并提供 3 个使用示例。

## 阶段二：值语义与句柄语义

**目标：** 理解 MATLAB 值类与 `handle` 类在赋值和修改时的区别。

任务：
- 阅读 [CH00205 对比实验](../CH002/CH00205/README.md)。
- 分别运行 `ValueCounter` 与 `HandleCounter`。
- 执行 `b = a` 后修改 `b`，观察 `a` 的状态。
- 说明共享状态可能造成的副作用。

验收：运行 `compareValueAndHandle` 并解释输出。

## 阶段三：封装与对象不变量

**目标：** 让对象始终处于有效状态。

任务：
- 阅读 CH00202 的私有写权限与输入校验。
- 在构造函数和 setter 中检查类型、尺寸与范围。
- 为无效采样率、空数据和错误维度设计清晰的报错行为。

验收：非法输入不能悄悄破坏对象状态；错误消息能帮助定位问题。

## 阶段四：继承、组合与多态

**目标：** 根据需求选择继承还是组合。

任务：
- 设计统一的传感器读取接口。
- 实现模拟温度传感器和压力传感器。
- 让采集器通过统一接口读取数据，不依赖具体传感器类名。

验收：新增一种传感器时，不需要重写采集器的核心流程。

## 阶段五：GUI 与硬件抽象

**目标：** 理解界面、业务逻辑和设备访问的职责边界。

任务：
- 阅读 [CH00203](../CH002/CH00203/README.md)、[CH00204](../CH002/CH00204/README.md) 与 [CH00206](../CH002/CH00206/README.md)。
- 运行 `demoDecoupledViewer` 和 `demoSensorPipeline`，观察 Viewer、采集模型、处理器和流水线各自的职责。
- 使用模拟数据验证采集、统计、时间戳、状态和错误记录，不依赖真实设备。

验收：硬件不可用时，仍可用模拟数据验证主要业务流程。

## 阶段六：单元测试与异常路径

**目标：** 用自动化测试保护类的行为。

任务：
- 使用 `matlab.unittest.TestCase` 为核心类编写测试。
- 覆盖正常输入、边界值、非法输入和状态变化。
- 对 GUI 和硬件依赖使用替身或模拟对象。
- 记录测试运行方式和 MATLAB 版本要求。

验收：测试可以重复运行；失败时能明确指出哪个行为不符合预期。

## 阶段七：综合项目

实现并扩展一个可测试的传感器数据处理工具（可从 [CH00206 工程流水线](../CH002/CH00206/README.md) 开始）：

- `DataAcquisitionModel`：协调采集并保存最近一次有效样本。
- `MockDataAcquisition`：生成可控的模拟数据。
- `SensorPipeline`：协调采集与处理，记录运行状态、时间戳和异常。
- `SensorDataProcessor`：计算统计指标，不负责 GUI 和硬件访问。
- `Viewer`：显示结果，不直接实现采集算法。
- `Test*`：覆盖核心逻辑和异常场景。

验收标准：
- 每个类有清晰且单一的职责。
- 算法可独立测试。
- 传感器可替换。
- 输入、输出和错误行为有文档。
- 提供一份从启动到查看结果的完整示例。

## 复盘标准

每个主题至少回答：
1. 这个设计解决了什么问题？
2. 是否有更简单的实现？
3. 对象状态可能在什么情况下变得无效？
4. 如何自动验证它的行为？
5. 如果未来增加一种实现，现有代码需要改多少？
